## 変更した動作

- 初回の名前入力後は、左・右・上・左上・右上を順に練習します。各方向の成功だけで進み、失敗や時間切れでは同じ方向を再提示します。5ボタンは固定し、押す方向と進捗を案内します。
- 練習はライフを減らさず、得点・連続成功・最大連続成功・成功数・ぴったり数・回復用連続数・試行数を本番へ加算しません。完了後は3・2・1から本番を開始し、追加の準備攻撃を挟みません。
- 遊び方からの任意練習は完了画面に留まります。練習のやり直しとホームへの移動を選べます。練習中のホーム移動、停止・再開にも対応します。
- 練習完了を `paripari.tutorial.v1` に保存します。保存の読み書きが失敗しても、同じ起動中は完了・名前・自己ベスト・設定を保持します。読み込みが成功して書き込みだけ失敗する場合も、古い値で上書きしません。
- 本番の準備攻撃と集計の扱いが変わるため、自己ベストのルール版を `r3-practice-20260927` に更新しました。R1/R2等の旧キーは削除・移行せず残します。
- 結果の再挑戦・ホームを詳細や共有より前へ置き、自己ベストと「成功のうち、ぴったりの割合」を表示します。判定と失敗理由を日本語にし、説明を現在の操作へ合わせました。
- メニューの縦スクロール、文字拡大、長い名前・得点、44pxの操作領域、画面切替時のフォーカスを調整しました。キーボード表示時はvisualViewportの高さを参照します。

## 検査範囲

| 検査 | 内容・証拠 |
| --- | --- |
| 単体 | `npm test`。従来31件＋Node 50件＝81件合格。全失敗・混合成功・5方向完了・本番無成功終了・任意練習・中断・古い結果・保存例外・書込のみ失敗・非表示共有欄へのフォーカス防止を追加 |
| 生成物 | `npm run build` で単一HTMLを再生成し、`npm run build:check` で一致確認 |
| ブラウザ | ChromiumとmacOS WebKitのQualityで実施。提出コミットの成否・件数はPR本文とActionsログへ固定する |
| 初回体験 | 分割版/単一HTMLそれぞれ、未完了状態から実際に生成される5方向を実キーで成功させ、本番で3回時間切れ→結果→再挑戦→ホームを確認。保存不可と再読込も検査 |
| 表示 | 320×568、375×500、375×667、402×874、1280×720、1920×1080。375×500では文字150/200%も追加。ホーム・説明・設定・停止・練習完了・結果の横溢れと操作到達、練習案内と基準位置・ボタンの重なり、visualViewport縮小時の開始ボタン到達を検査 |
| R2回帰 | 30/60/120fps、配送0/16/50ms、実時間のキー・タッチ、250ms超の停止、縦横・離脱を維持 |
| 独立レビュー | 実装担当と別のSol Highで差分を確認。確定した結果と必要修正はPR本文に記録 |

表示検査はレイアウト用の画面表示fixtureを使い、遷移検査とは区別しています。練習のブラウザ検査は完了状態や得点を直接書き換えず、製品の入力・時計・判定を通します。ローカル環境にはブラウザ実行ファイルがないため、ブラウザ合否はGitHub Actionsを根拠にします。
