作成日：2026-09-22（日本時間）
正本：[実装計画書](IMPLEMENTATION_PLAN.md)／結果記録先：[進捗](PROGRESS.md)

以下はこれから実装する検査条件です。この一覧の存在は、検査実行や合格を意味しません。各IDについて、対象コミット、条件、入力記録、期待値と実測値、実行コマンド、実施環境、証拠の保存先、合否を記録します。未実施と失敗を合格に含めません。

## 1. 検査環境と共通規則

純粋なゲーム処理では、時刻・入力・乱数を外から指定して同じ試合を再現します。画面の装飾用乱数とは分けます。ブラウザ検査は、実際の入力配線と生成物を使い、純粋関数だけ通して画面の起動確認の代わりにしません。

自動ブラウザ検査はChromiumとWebKitを基本とし、PCのキーボード/マウスとスマホ相当のタッチ入力を分けます。WebKit自動検査でもiPhone実機とは記録しません。検査用の名前・得点は端末内の隔離した領域を使い、外部へ送信しません。

表示サイズはCSSピクセルで320×568、375×500、375×667、402×874、1280×720、1920×1080を含めます。402×874は検査用の寸法であり、iPhone 17 Pro実機の表示領域を測定した値ではありません。実機では実際の表示領域とブラウザの版を別に記録します。スマホ横向き、ソフトウェアキーボード、表示倍率100/150/200%も確認します。

元からある `npm test` と `npm run build` を維持し、追加検査の実行方法をREADMEへ記載します。未実装のコマンドを実行済みと報告しません。既存期待値を変更する場合は、新仕様の根拠と変更前後を記録します。

## 3. 時刻と判定

各検査は正しい方向と誤った方向、単発と分割攻撃の両方で実施します。比較対象は得点だけでなく、判定列、ライフ、連続数、次の出現予定、乱数状態も含みます。

| ID | 条件・操作 | 期待結果 |
| --- | --- | --- |
| T01 | 誤差0、±59、±60、±61、±139、±140、±141ミリ秒で押す | ±60まで完全成功、±140まで成功、それ以外は失敗。方向違いは成功しない |
| T02 | 同じ入力時刻を30/60/120回毎秒の描画予定で再生する | 全判定と最終集計が一致。直前の描画933.33、到達1000、入力950なら完全成功 |
| T03 | 同じ入力を0/16/50ミリ秒遅れて配送し、期限近くで更新順も入れ替える | 時間内の入力は採用方式の保証範囲で同じ結果。押下自体が+141なら配送待ち中でも失敗 |
| T04 | +140の入力と期限切れ更新を同時刻にし、処理順を変える | 有効入力が優先されて成功。確定後の二重加点や結果の復活なし |
| T05 | 80ミリ秒の描画間隔、採用した停止境界の直前/直後、長い処理停止を再現する | 通常の遅い描画では時間を切り捨てない。長い途絶は明示した規則で停止し、復帰でまとめて被弾しない |
| T06 | 動きを抑える設定のON/OFF、描画効果0/最大、振動可/不可で同じ試合を再生する | 判定・ライフ・得点・攻撃時刻・ゲーム用乱数が完全一致 |
| T07 | 開始、停止、再開を含む時刻変換、無効/0/異常なイベント時刻、前の試合の時刻を与える | 時刻基準を混ぜず、古い入力で成功しない。代替規則を記録し、端末の実遅延とは区別する |

## 10. 合格の扱い

B/T/I/S/G/U/D/H/Qは公開候補の自動・手動検査の必須範囲です。Q04の独立レビューとX01/X02の実機確認を、AIの自己申告や模擬端末の検査で置き換えません。X03は公開準備の検査であって、公開実行ではありません。

一部が未実施でも、修正とDraft PRは作成します。ただし、進捗には未実施として残し、「完成」「公開可能」「実機確認済み」とは報告しません。人の体感や面白さについては確認者と条件を残し、自動プレイだけで楽しいと断定しません。
