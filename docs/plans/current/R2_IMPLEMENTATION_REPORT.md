## 採用する時間と順序

入力の発生時刻、攻撃の到達、リングの描画を同じゲーム時計へ写します。時計は単調な実時間を基準とし、停止時間を除外します。描画間隔の50ミリ秒切り捨てと、成功演出によるゲームの停止・減速を撤去します。見た目の更新量だけは制限できます。

計画書の配送待ち100ミリ秒は初期案です。R2では操作への返答を早めるため、保証する配送遅れを **0〜50ミリ秒（両端を含む）** とし、確定を待つ時間を50ミリ秒に短縮します。発生時刻が「現在のゲーム時刻−50ミリ秒」より古くなった入力だけを時刻順に確定します。等しい時刻ではまだ確定しないため、50ミリ秒遅れの入力が同時刻の更新処理の後に届いても取りこぼしません。判定表示には50ミリ秒と次の描画までの待ちが生じます。押したボタンの反応は即時に表示します。

| 条件 | 処理 |
| --- | --- |
| 同じ発生時刻の複数入力 | 方向の固定順 `L → DL → D → DR → R` で1件だけ採用。同方向の重複も1件 |
| 入力と期限が同じ時刻 | 入力を先に処理。誤差±140ミリ秒を成功側へ含む |
| 入力自体が+141ミリ秒 | 配送待ち中でも成功にしない |
| 配送に50ミリ秒を超えた入力 | 破棄。確定した結果を復活させない |
| 最初の部分の早押し | 出現後なら失敗として判定 |
| 2個目以降の部分 | 前の部分が確定済み、かつ自分の到達−140ミリ秒以後だけを受け付ける。それ以前の連打は無視 |
| 次の出現 | 最後の到達予定＋140ミリ秒＋抽選済み間隔を基準にする。早押しや演出で前倒ししない |
| 出現・描画 | 入力確定の待ち時間を出現時刻へ加えず、予定時刻の攻撃を同じ時計で描く |

ゲーム用乱数は攻撃方向・必要回数・速度・出現間隔だけで消費します。描画や粒子の乱数から分離し、検査では同じ乱数列を注入します。ルールが変わるため自己ベストの保存先もR2用に分け、R1以前の記録は残します。

## 停止と再開

開始前、練習、本番、再開前を区別し、非表示・ページ離脱・スマホ横向きで停止します。戻っただけでは再開せず、明示的な再開から3・2・1を経ます。カウント終了時にも表示状態と向きを確認し、1回だけ開始します。ホームへの移動や新しい試合で古い入力・遷移を無効にします。

描画の途絶が250ミリ秒を超えた場合は、判定処理を進める前に最後に表示した時点で停止し、未確定の入力を破棄します。250ミリ秒ちょうどまでは通常進行です。この長い途絶の停止規則は、通常の配送遅れ保証より優先します。通常の一時停止では、既に受理した未確定入力と判定待ちを凍結します。

イベントの時刻は元の値を保持し、必要な場合だけ `performance.timeOrigin` を使って同じ基準へ変換します。0・欠落・非有限値は配送された時刻を代替値とし、未来の値、現在の実行区間より古い値、保証を超える配送遅れを新しい入力へ置き換えません。
